# Team Charter: Stop De Ontkoking

## 1. Onze Ambitie
* willen als team minimaal een 8 halen voor het project. Daarnaast willen we leren om goed samen te werken met GitHub, duidelijke afspraken te maken en onze programmeer- en designvaardigheden te verbeteren.

## 2. Rol- en Taakverdeling
*Iedereen schrijft code en ontwerpt, maar de Leads hakken de knopen door bij twijfel.*

* **Scrum Master:** Sem *(Verantwoordelijk voor Stand-ups, GitHub Projects board en communicatie)*
* **Lead Design:** [Naam] *(Bewaakt visuele stijl en UI/UX keuzes)*
* **Lead Git/Dev:** [Naam] *(Bewaakt code quality en let streng op PR's)*

## 3. GitHub & Code Afspraken
* **Branching:** Niemand commit rechtstreeks naar `main`. We werken via aparte branches.
* **Pull Requests (PR):** Een PR mag pas worden gemerged als minimaal 1 ander teamlid een "Approve" (Code Review) heeft gegeven.

## 4. De Pre-Mortem (Risico Analyse)
*Fast-forward naar week 7: het project is genadeloos gefaald. Wat ging er mis en hoe voorkomen we dit nu al?*

* **Risico 1:** We lopen vast op technische problemen.
* *Oplossing vooraf:* Als we langer dan 1 uur vastlopen, vragen we hulp aan een teamlid of de docent in plaats van te lang alleen door te gaan.

* **Risico 2:** Teamleden zijn slecht bereikbaar buiten de les.
* *Oplossing vooraf:* We reageren tijdens werkdagen binnen maximaal 4 uur op belangrijke berichten in Teams.

* **Risico 3:** Taken worden niet op tijd afgemaakt.
* *Oplossing vooraf:* We verdelen alle taken via GitHub Projects en bespreken aan het einde van iedere les de voortgang. Als iemand achterloopt, melden we dit zo snel mogelijk aan het team.

## 5. Consequenties
* Als iemand structureel afspraken niet nakomt, bespreken we dit eerst tijdens de stand-up en geven we feedback. Bij een tweede keer spreken we duidelijke verbeterafspraken af. Als het daarna nog steeds niet beter gaat, informeren we de docent.
