# Team Charter: Stop De Ontkoking

# 1. Onze Ambitie
Wij willen als team minimaal een 8 halen voor het project. Daarnaast willen we leren om goed samen te werken met GitHub, duidelijke afspraken te maken en onze programmeer- en designvaardigheden te verbeteren.

## 2. Rol- en Taakverdeling
*Iedereen schrijft code en ontwerpt, maar de Leads hakken de knopen door bij twijfel.*

# Taakverdeling week 1:
* Musab:  Doelgroep + inspiratie onderzoeken, moodboard uitwerken.
* Sem:  Doelgroep onderzoeken + Doelgroep analyse uitwerken + back log bijwerken
* Diego: Project onderzoeken, Projectplan opstellen en uitwerken.

## 3. GitHub & Afspraken
- Branching:** Niemand commit zonder overleg.
- Pull Requests (PR): Een PR mag pas worden gemerged als minimaal 1 ander teamlid een "Approve" heeft gegeven.

## 4. De Pre-Mortem (Risico Analyse)
Voorbeeld: Stel het project is genadeloos gefaald. Wat ging er mis en hoe voorkomen we dit nu al?

* **Risico 1:** We lopen vast op technische problemen.
* *Oplossing vooraf:* Als we lang vastlopen, vragen we hulp aan een teamlid of de docent in plaats van te lang alleen door te gaan.

* **Risico 2:** Teamleden zijn slecht bereikbaar buiten de les.
* *Oplossing vooraf:* We reageren tijdens werkdagen op belangrijke berichten in Teams.

* **Risico 3:** Taken worden niet op tijd afgemaakt.
* *Oplossing vooraf:* We verdelen alle taken via GitHub Projects en bespreken aan het einde van iedere les de voortgang. Als iemand achterloopt, melden we dit zo snel mogelijk aan het team.

## 5. Consequenties
* Als iemand structureel afspraken niet nakomt, bespreken we dit eerst tijdens de stand-up en geven we feedback. Bij een tweede keer spreken we duidelijke verbeterafspraken af. Als het daarna nog steeds niet beter gaat, informeren we de docent.
